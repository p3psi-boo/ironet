# 应用层自学习与自适应控制：算法设计背景

> **当前运行时与部署规范**：策略 ABI、组件装载、签名、热切换和回退以[策略运行时架构](策略运行时架构.md)、[配置参考](配置参考.md)及[开发与测试](开发与测试.md)为准。
>
> daemon 默认 `builtin` 在进程内运行 `CorePolicy`；外部 `.wasm` 初始加载失败回退到该 builtin core；`native` 仅在显式选择时运行保守宿主规则。`builtin.wasm` 是 bit-exact guest fixture 与外部组件模板，只有 `ironet policy replay --policy builtin` 刻意经 loader 运行它来做对照。
>
> 本文保留效用函数、遥测、BBR3 和实验方法的设计背景；其中引用 JSON `PolicyArtifact`、旧行号或旧实施排期的内容均为历史记录，不可作为当前配置或验收入口。

目标：让 `ironetd` 在不同带宽、时延、丢包环境下**自动**找到吞吐、延迟、稳定性与资源消耗的平衡点，并跨会话记住学到的东西。本文保留原始设计与实施背景；实现时应以符号名和当前架构文档重新定位。

## 0. 一页纸总览

- **三层结构**：快环（BBR3 + 护栏，每包/每轮，不学习）→ 慢环（每 1 s：遥测 → 效用 U → 学习器 → 动作）→ 记忆（per‑peer × 上下文先验，落盘）。
- **现有机制全部保留并复用**：`AutoTunerV2::observe_at`（纯函数、可回放）、`TuneDecisionV2` 作为应用契约、`RuntimeMetrics` 计数器、`FecFeedbackV2` 反馈通道（wire 首次稳定前可演进）、`CpuSampler`、`deployment::atomic_write`、status/Prometheus 管线、netem 矩阵。
- **效率来自四个决定**：
  1. 先装"尺子"（效用 + 录制/回放），再动行为；
  2. BBR3 可调化时默认值 = 现状，先"接通"再"学习"；
  3. 学习器先跑 **shadow 模式**（只算不应用、只记日志），用回放和矩阵离线验证后再打开；
  4. 三条工作线（BBR3 / 遥测+效用 / 测试设施）互相独立，可并行；
  5. 策略是可替换的版本化产物（`PolicyArtifact`：V1 内嵌，V2 以文件热加载、shadow 灰度后切换），运行时只依赖稳定的 `Policy` 接口与护栏。
- **总工期约 4 周**（单人串行）/ 2.5 周（两人并行）。

### B3. 效用函数（1 天）
新文件 `src/protocol/v2/utility.rs`：

```rust
pub enum Objective { Balanced, Throughput, Latency }
pub struct UtilityWeights { pub throughput: f64, pub queue_delay: f64, pub latency_sojourn: f64,
    pub residual_loss: f64, pub jitter: f64, pub cpu: f64, pub wire_overhead: f64, pub memory: f64 }
pub struct UtilitySample { pub total: f64, pub components: [f64; 8], pub goodput_bytes_per_second: u64 }
pub struct UtilityEstimator { window: VecDeque<u64> /* 8 个 goodput */, weights: UtilityWeights }
impl UtilityEstimator {
    pub fn observe(&mut self, t: &PathTelemetryV2, d: &TuneDecisionV2, wire: &TxByteBreakdownV2) -> UtilitySample;
}
```

公式（与 `tuning.rs` 同一套 EWMA 平滑值）：
```
U = w_t·ln(1 + goodput_rx/1 Mbit/s)
  − w_d·max(0, queue_delay/max(5 ms, 0.5·min_rtt) − 1)
  − w_p·latency_sojourn_p95/20 ms            // 仅 latency_queue 近期非空时
  − w_l·residual_loss_ppm/10_000
  − w_j·cv(goodput, 8 样本)
  − w_c·cpu_per_mille/1000
  − w_o·(parity+repair+cover+envelope)/payload  // 来自 TxByteBreakdownV2
  − w_m·(send_buf+recv_buf+repair_cache)/32 MiB
```
`Balanced` 权重起点：t=1.0，d=0.8，p=0.8，l=1.0，j=0.3，c=0.3，o=0.4，m=0.1；`Throughput`：t=1.5，d=0.4，p=0.2；`Latency`：t=0.6，d=1.5，p=1.5。权重不是用户旋钮，只有 `objective` 可配。
单测：各分量单调性；`goodput` 受 wire 开销抵消；`Latency` 意图下队列惩罚支配。

### C3. 学习算法（作为策略核心的第一个实现 `bandit-vivace`）

当前实现以 `ironet-policy-core` 的 `LearnerStateV1` 为唯一学习器状态，宿主侧
`learner.rs` 只保留上下文、动作和 trace 投影。下面的 trait 草图是早期设计记录，
不再对应生产 API；生产调用统一经过 `PolicyBackend` / `PolicyTickV1`。
```rust
/// 策略接口：运行时只认这个 trait（见 §C7）。
pub trait Policy: Send {
    fn id(&self) -> PolicyId;                       // 如 "bandit-vivace@1"
    fn warm_start(&mut self, memory: &PolicyMemory); // 从记忆/先验恢复
    fn step(&mut self, now: Instant, t: &PathTelemetryV2, u: &UtilitySample,
            g: &GuardrailsV2, baseline: &PolicyV2) -> (ActionV2, LearnerTrace);
    fn export_memory(&self) -> PolicyMemory;         // 供持久化
}
pub struct Learner { mode: LearnerMode /*Off|Shadow|On*/, active: Box<dyn Policy>,
    shadow: Option<Box<dyn Policy>> /* 候选版本并行评估 */, memory: MemoryHandle }
pub struct BanditVivacePolicy { artifact: PolicyArtifact, ctx: Option<ContextKey>,
    bandit: HashMap<ContextKey, PresetPosterior>, fine: FineTuner, dwell: DwellState, rng: SmallRng }
```
- **预设层**：每个上下文桶 Thompson Sampling（高斯后验，奖励 = 停留期平均 U）。探索条件：同 `path_epoch` ≥ 10 s、`!cpu_limited`、最近 3 样本无 `emergency`、`sample_count ≥ 8`。最小停留 `max(3 s, 8×RTT, 一个 ProbeBW 周期)`。
- **连续层**（PCC‑Vivace 式）：在当前预设周围，每次只动一个维度（`up_gain`→`headroom`→`cwnd_gain`→FEC 冗余→train），θ+δ、θ−δ 各跑一个监测区间，按 ΔU 符号与幅度移动；连续同向成功步长 ×1.5，失败步长 ÷2 并回退。
- **回滚**：新动作首个完整区间 U < 基线 × 0.9 → 立即回退并惩罚；`emergency`/`path_epoch` 变化 → 中止探索回到该桶最优。
- **Shadow 模式**：`step` 正常计算与记忆更新，但 `tuner_loop` 仍应用 baseline；`LearnerTrace` 记录"若应用会怎样"，回放工具用录制数据估算差异。
- 所有随机性来自注入的 `SmallRng`（seed 可配），保证回放可重现。

### C5.1. 当前算法与状态收敛（已实现）

- 路由标签按 `source × owner × candidate-path` 生成，同一 owner 的多个前缀共享路径标签；最长前缀和 underlay 排除都使用稀疏长度索引，不再预分配 33/129 组表。
- mesh 控制面将 Presence 更新合并到 latest-value compiler actor；阻塞编译在 `spawn_blocking` 中完成，并只构建本机 `DataplaneSnapshotV2`。
- 每流 lease 只保留 snapshot generation，候选路由使用内联 `SmallVec`；单邻接和 mesh 流表删除重复的 `last_seen`/已选路由状态，容量反馈窗口使用单调最大值队列，摊销 O(1)。
- `AutoTunerV2` 持有唯一 `HostLimitsV1`/guardrails；`PolicyTickV1` 以 `EffectiveActionV1` 为标准中间态，只在输入/输出边界做一次投影。
- 远端反馈是一个带 3 s TTL 的派生速率窗口；路径遥测的快照、时钟、epoch 和失败计数收敛到一个状态对象。`min_rtt` 使用拥塞控制器的当前窗口，不再保留进程生命周期最小值。
- WASM 热更与策略持久化分别由显式状态机驱动；文件读取、摘要校验和组件加载全部移出 async 热路径。
- PMTU 限制按 route epoch 隔离，新 epoch 原子换代旧表，旧 epoch 的迟到 OAM 不会污染新路由。

### C7. 可替换的策略模块与版本化（历史 JSON 设计）

"可替换"在这里有三层含义，分别用不同机制解决：

| 层 | 变化的是什么 | 机制 | 换代方式 |
| --- | --- | --- | --- |
| 算法代码 | `Policy` 的实现（bandit‑vivace → 以后换成别的） | `Box<dyn Policy>`，编译进二进制，按 `PolicyArtifact.algorithm` 选择实现 | 随软件发布 |
| 策略产物 | 预设表、上下文分桶边界、效用权重、探索/停留/回滚参数、各桶初始先验（= 训练出来的 V1/V2） | `PolicyArtifact` JSON 文件，运行时加载、可热替换 | 不改代码、不重启 |
| 学到的记忆 | per‑peer × 上下文后验与参数 | `MemoryFile`，带 `policy_id` 与 `schema_version` | 随产物版本迁移或丢弃 |

**稳定契约**（策略怎么换都不能越过）：`Policy` trait、`PathTelemetryV2`/`UtilitySample` 输入、`ActionV2` 输出、`GuardrailsV2::constrain` 与 BBR3 内部夹紧（§A2）。因此任何版本的产物都只能在安全集合内行动。

**产物格式** `src/protocol/v2/policy.rs`：
```rust
pub struct PolicyArtifact {
    pub schema_version: u32,            // 产物格式版本，运行时只接受已知版本
    pub id: String,                     // 如 "bandit-vivace@2"，算法名@产物代
    pub algorithm: String,              // 选择 Policy 实现
    pub built_at: String, pub trained_on: Vec<String>,  // 场景/录制来源，便于审计
    pub contexts: ContextSchema,        // 分桶边界
    pub presets: Vec<PresetSpec>,       // 名称 + Bbr3Proposal + FEC 族 + 适用上下文
    pub priors: BTreeMap<ContextKey, PresetPosterior>,  // 训练出来的初始后验
    pub weights: BTreeMap<Objective, UtilityWeights>,
    pub exploration: ExplorationSpec,   // dwell、步长、回滚阈值、稳态条件
    pub digest: String,                 // blake3，加载时校验
}
```
历史设计曾假定 `builtin` 产物由 `include_str!` 内嵌（即 V1），并允许文件产物覆盖；这不是当前 daemon 契约。当前 builtin 是 in-process core，外部 `.wasm` 加载失败回退到该 core，`builtin.wasm` 只保留为 bit-exact guest fixture 与外部组件模板。其余加载失败、热替换与记忆迁移描述仅保留为方案演进记录。

**训练与换代流水线（V1 → V2）**：
1. 录制：矩阵 + 真实链路跑 `mode=shadow|on`，得到 JSONL 样本（§B4）。
2. 训练：`examples/autotune_train.rs` 离线读取样本，用回放器对候选 `PolicyArtifact`（预设网格、权重、探索参数、先验）评估平均 U 与 regret，选优并写出 `policy.v2.json`（含 `trained_on` 与 `digest`）。训练就是"在回放上做超参搜索 + 先验估计"，不需要 GPU。
3. 验证：`scripts/autotune-oracle.sh` 与矩阵对 V1/V2 各跑一遍，比较 §7 指标。
4. 灰度：部署时设 `shadow_policy = "/etc/ironet/policy.v2.json"`，守护进程同时运行 V1（应用）与 V2（只算不应用），`LearnerTrace` 同时记录二者的估计 U；`summary.json`/status 的 `policy.shadow_advantage` 给出差值。
5. 切换：`policy = "/etc/ironet/policy.v2.json"` + `ironet reload`；回退同理改回 V1。
6. 历史计划：V2 稳定后以 `include_str!` 替换 `builtin`，下个软件版本默认生效；当前实现已改为 in-process core，guest 不走 daemon 默认路径。

**版本兼容规则**：`schema_version` 只增不减；运行时保留最近两个 schema 的解析器；`MemoryFile` 记录产物 `id`，产物升级后首次加载时按上述迁移规则处理；status 在 `policy.live.policy_id`、`policy.policy_source` 和可空 `policy.shadow.policy_id` 暴露策略身份。

## 9. 风险与边界

- **探索有代价**：只在稳态小步探索；快速变化由 BBR3 与护栏即时处理。
