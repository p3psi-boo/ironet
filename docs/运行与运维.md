# 运行与运维

## 服务模型

`ironetd` 是管理 TUN、策略路由和覆盖数据面的守护进程。`ironet` 是操作 CLI；它通过默认路径 `/run/ironet/control.sock` 与守护进程通信。

systemd unit 使用 `ironet` 系统用户运行守护进程，仅授予 `CAP_NET_ADMIN`，并限制可写路径到配置、运行时和状态目录。安装包同时提供最小 polkit 规则，只允许该系统用户调用 systemd-resolved 的 per-link DNS 设置与回滚动作；不会授予其他管理动作。NixOS 模块会启用 systemd-resolved、polkit 并安装同一规则。控制套接字权限为 `0660`；默认只有套接字所属用户和组能访问。以 `sudo` 执行 CLI 是最直接的操作方式。

## 服务管理

```bash
sudo systemctl enable --now ironet
sudo systemctl status ironet
sudo systemctl reload ironet
sudo systemctl restart ironet
sudo journalctl -u ironet -f
```

服务启动前会执行 `ironet doctor`。若配置、摘要、身份文件权限、内核能力或底层路由不满足要求，服务不会启动。

从源码通过 `scripts/install.sh` 安装的 unit 默认从 `/usr/local/bin` 启动；Debian 包安装的 unit 使用 `/usr/bin`。不要在同一主机上混用两种安装方式，以免 unit 与实际二进制路径不一致。

卸载源码安装的二进制和 unit：

```bash
sudo scripts/uninstall.sh
```

该脚本保留 `/etc/ironet` 和 `/var/lib/ironet`，便于后续重新安装或人工清理。

## 运行状态

```bash
sudo ironet health
sudo ironet status
sudo ironet status --output json
sudo ironet peers --output jsonl
sudo ironet metrics
sudo ironet tui --interval-ms 1000
```

| 命令 | 用途 |
| --- | --- |
| `health` | 守护进程已就绪且状态仍在有效期内时返回 0。适合 systemd、监控探针和脚本。 |
| `status` | 输出最后一次发布的完整运行时状态。 |
| `peers` | 输出当前邻接、所选 QUIC 传输、RTT、PMTU、拥塞窗口、V2 队列和方向性计数。 |
| `metrics` | 从实时 V2 snapshot 输出 Prometheus 文本格式的 `ironet_v2_*` 指标。 |
| `tui` | 交互式运维台：持续刷新 peer 指标、审核 Presence 路由、执行节点 ping/trace，并可 reload 守护进程。`top` 是兼容别名。 |
| `ping 地址` | 对目标覆盖地址发送受限的应用层探测。 |
| `trace 地址` | 输出 V2 数据面 当前选择的覆盖路径和节点信息。 |

`ping` 默认发送 4 个探测，每个探测超时 1000 ms。可按需调整：

```bash
sudo ironet ping --count 10 --timeout-ms 2000 --output json 21.0.0.3
sudo ironet trace --max-hops 8 --timeout-ms 2000 21.0.0.3
```

`tui` 中按 `Tab` 在 Peer、Routes、Diagnostics 三个视图间切换。Routes 视图区分 `DECLARED`、`ACCEPTED`、
`OFFLINE` 和 `CONFLICT`：

- `a`：接受所选声明，把前缀与声明节点写入 `routes.toml` 并 reload；
- `x` 两次：移除所选持久路由并 reload，二次按键用于避免误操作；
- `j`/`k`：选择项目；`r`：立即刷新；空格：暂停/继续刷新；
- Diagnostics 中 `p`：ping 所选节点，`t`：trace 所选节点；
- 任意视图中按两次 `R`：校验当前配置并 reload 守护进程。

接受的含义是把动态 Presence 声明固定到本地路由文件。移除只删除这份本地固定记录；
若节点仍通过 mesh 声明该前缀，路由会继续作为动态声明生效，并重新显示为 `DECLARED`。
冲突或隔离中的声明会显示为 `CONFLICT`，需要先解决前缀归属冲突。

## 文件与日志

默认路径：

| 路径 | 内容 | 访问注意事项 |
| --- | --- | --- |
| `/etc/ironet/config.toml` | 活动配置 | 包含网络 ID 和 peer 信息；按部署策略限制读权限。 |
| `/etc/ironet/config.toml.blake3` | 配置 BLAKE3 摘要 | 由 `seal-config` 或 `install-config` 写入。 |
| `/etc/ironet/config.toml.previous` | 上一份配置 | 仅在 `install-config` 后存在。 |
| `/var/lib/ironet/routes.toml` | CLI 管理的静态远端路由 | 由 `route import/remove` 原子更新，不写入主配置。 |
| `/var/lib/ironet/identity.key` | iroh 节点身份私钥 | 权限必须为 `0600`。 |
| `/var/lib/ironet/identity.key.derp` | DERP 身份私钥 | 仅 DERP 模式使用，权限必须为 `0600`。 |
| `/run/ironet/status.json` | JSON 状态快照 | 刷新间隔由配置决定。 |
| `/run/ironet/control.sock` | CLI 控制套接字 | 不应暴露到网络。 |

日志默认写入 systemd journal。设置 `RUST_LOG` 可以调整 Rust 日志过滤条件，设置 `IRONET_LOG_FORMAT=json` 可输出 JSON 格式日志；两个环境变量已在默认 unit 中配置。

## V2 遥测

`ironet status --output json`、`ironet peers --output jsonl` 与 `ironet metrics` 直接读取当前 V2 runtime state，包含 QUIC path、PacketTrain/Cell、Latency/Bulk 调度、FEC/Repair、GSO/PMTU 和丢弃计数。`metrics` 使用 Prometheus text exposition，所有名称均位于 `ironet_v2_*` 命名空间。V1 的定时文本文件和旧指标名称已删除；需要 textfile collector 时由定时器原子写入 `ironet metrics` 的标准输出。

## 配置变更与回退

### 手工变更

```bash
sudoedit /etc/ironet/config.toml
sudo ironet validate --config /etc/ironet/config.toml
sudo ironet seal-config --config /etc/ironet/config.toml
sudo systemctl reload ironet
sudo ironet health
```

`reload` 由守护进程重新读取、校验并激活配置。配置摘要未更新时，加载会失败；不要通过删除摘要文件跳过校验。

### 候选文件与回退

```bash
sudo install -m 0600 ./config.toml.candidate /etc/ironet/config.toml.candidate
sudo ironet install-config \
  --source /etc/ironet/config.toml.candidate \
  --config /etc/ironet/config.toml
sudo systemctl reload ironet
```

`install-config` 在写入前校验候选文件，并在替换前保留上一份配置。新配置导致问题时：

```bash
sudo ironet rollback-config --config /etc/ironet/config.toml
sudo systemctl reload ironet
sudo ironet health
```

## 身份备份与恢复

在离线或受控位置保存身份备份。身份恢复会保持 endpoint ID；恢复到已经存在身份文件的路径会被拒绝。

```bash
sudo ironet backup-identity \
  --config /etc/ironet/config.toml \
  --output /root/backup/identity.key

sudo systemctl stop ironet
sudo mv /var/lib/ironet/identity.key /var/lib/ironet/identity.key.lost
sudo ironet restore-identity \
  --source /root/backup/identity.key \
  --identity-file /var/lib/ironet/identity.key
sudo systemctl start ironet
```

若启用了 DERP，`backup-identity` 会同时生成同目录的 DERP 身份备份；恢复时也会恢复对应文件。

## 常见检查顺序

### 服务无法启动

```bash
sudo systemctl status ironet --no-pager
sudo journalctl -u ironet -b --no-pager
sudo ironet validate --config /etc/ironet/config.toml
sudo ironet doctor --config /etc/ironet/config.toml
```

依次确认：配置和摘要是否匹配、身份文件是否存在且权限正确、`/dev/net/tun` 是否可用、运行身份是否有 `CAP_NET_ADMIN`、`iproute2` 是否可执行、默认 NAT 所需的 `iptables`/`ip6tables` 是否可用，以及固定 peer 的底层路由是否没有指向 `ironet0`。

### peer 未连接或反复切换

```bash
sudo ironet peers --output json
sudo ironet status --output json
ip route get 对端公网地址
```

确认网络 ID 相同、endpoint ID 没有写错、直连地址端口可达、配置的 relay/DERP 服务可用，以及对端公网地址的底层路由没有递归进入覆盖接口。查看 `selected_transport`、RTT、丢包和 `path_epoch` 可判断是否发生底层传输切换；切换后旧容量样本会失效并重新测量。

### 可以连接但无法访问远端前缀

检查以下内容：

1. 本节点和远端前缀没有重叠；
2. mesh 关闭时，`ironet route list` 中的路由与 `allowed_source_prefixes` 完整且精确匹配；
3. 需要多跳时，确认中转节点没有显式设置 `routing.transit_enabled = false`；该能力默认开启；
4. 默认 NAT 模式下，`iptables`/`ip6tables` 中的 `IRONET_NAT_POSTROUTING` 规则有命中；关闭 `routing.nat_enabled` 时，本地 LAN 和远端 LAN 都有指向各自覆盖节点的回程路由；
5. 主机转发 sysctl 和防火墙规则允许预期流量。

使用 `trace` 确认覆盖路径，再分别检查各跳的 `peers` 状态。

### MagicDNS 名称不能解析

```bash
sudo resolvectl status ironet0
sudo resolvectl query edge-a
sudo ss -lntup | grep ':1053'
jq .dns /run/ironet/status.json
```

确认 `ironet0` 上有网络专属路由域、DNS 地址包含端口 1053，且状态中的
`catalog_generation`、`nodes` 正常增长。`accept_dns=false` 时权威服务器仍运行，
可用 `dig @本机Overlay地址 -p 1053 edge-a.<domain>` 验证。若 systemd-resolved
重启导致 per-link 设置丢失，reload 或重启 ironet 会重新注册；ironet 正常停止时会
执行 `RevertLink`，不保留全局 DNS 修改。

### 配置摘要不匹配

只在已经审阅 TOML 内容后执行：

```bash
sudo ironet validate --config /etc/ironet/config.toml
sudo ironet seal-config --config /etc/ironet/config.toml
```

若未知进程修改了配置，应先恢复受信任版本，再重新生成摘要。
