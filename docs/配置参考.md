# Ironet Protocol V2 配置参考

V2 配置只描述身份、locator、路由策略和 cover profile。发送缓冲、接收缓冲、PacketTrain、quantum、PMTU、FEC/Repair、批处理、pacing、拥塞控制和 lane 数量全部由运行时闭环协商，不再暴露旧协议调参项。

修改部署期参数后重新密封、校验并滚动 reload 即可，无需重新编译：

```bash
sudo ironet seal-config --config /etc/ironet/config.toml
sudo ironet validate --config /etc/ironet/config.toml
sudo systemctl reload ironet
```

## 根字段

| 字段 | 默认值 | 说明 |
|---|---:|---|
| `network_id` | 必填 | 网络成员资格密钥；只在 TLS 后的 SessionHello 中证明。 |
| `identity_file` | 必填 | iroh Ed25519 节点身份文件路径；新配置首次执行 `seal-config` 或 `install-config` 时以 `0600` 创建。已加入网络的节点若丢失该文件，必须从备份恢复或执行显式 rejoin，运行、校验和查询命令不会静默更换 EndpointId。 |
| `bind_addresses` | `[]` | 最多一个双栈 UDP 地址；为空时使用 `[::]:4000`。 |
| `excluded_underlay_prefixes` | `[]` | 禁止直连路径使用的地址前缀；例如用 `200::/7` 排除 Yggdrasil。 |
| `tun_mtu` | `32768` | TUN 记录上限；超过上限的 GSO aggregate 在入口按段拆分，实际 QUIC DATAGRAM ceiling 由 PMTU 自动决定。 |
| `node_interface` | `ironet0` | Linux TUN 名称。 |
| `node_addresses` | `[]` | 本节点稳定 overlay 地址。 |
| `advertised_prefixes` | `[]` | 本节点发布的 LAN/服务前缀。 |

配置使用 `deny_unknown_fields`。已移除的协议字段会直接报错，不会静默忽略或触发回退。

## `[cover]`

```toml
[cover]
sni_pool = ["media.example"]
profile_id = 1
```

- `sni_pool` 是网络级可见 SNI 池；运行时按 network、EndpointId 对和 generation 稳定选择。
- `profile_id` 非零；变化只影响新连接。
- 对外 ALPN 固定为 `h3`。真实 EndpointId、network ID 与能力只在加密后的 `ISV2` SessionHello 中认证。

## `[[peers]]`

```toml
[[peers]]
name = "branch-b"
endpoint_id = "ENDPOINT_ID"
direct_addresses = ["[2001:db8::10]:443"]
# derp_public_key = "DERP_PUBLIC_KEY"
```

每个 peer 必须至少有 direct locator、DERP locator 或一个 exclusive private link。多个 IPv4/IPv6 locator 属于同一逻辑 V2 adjacency，路径迁移不会替换 flow lease 或 route generation。

## `[relay]`

```toml
[relay]
servers = ["https://derp-1.example.net/derp"]
```

仅配置 Tailscale DERP custom transport。配置 `servers` 后，每个使用 DERP 的 peer 要有独立 `derp_public_key`；DERP 仍承载端到端 QUIC。

## `[[links]]`

```toml
[[links]]
name = "iepl-ab"
peer_id = "ENDPOINT_ID"
exclusive = true
fallback = false
remote_addresses = ["10.255.0.2:443"]
```

Private link 只是 locator 约束，不引入第二套会话协议。当前只接受 `exclusive = true`、`fallback = false`，身份和网络成员资格仍由 V2 SessionHello 验证。

## `[routing]`

```toml
[routing]
isolate_overlay = true
transit_enabled = true
rule_priority = 10000
table = 211
allow_default_routes = false
nat_enabled = true
# max_egress_mbps = 80
```

- `transit_enabled` 默认开启，控制 overlay peer 之间的中转；只在明确不允许本机承担中转时关闭。
- `nat_enabled` 对进入本节点已发布子网的 overlay 流量执行 connmark + MASQUERADE。
- `/0` 必须显式启用 `allow_default_routes`，并且禁止 DERP，避免管理面路径被覆盖。

## `[mesh]`

```toml
[mesh]
enabled = true
max_peers = 12
```

V2 使用经过 owner 签名和 network membership tag 验证的 `PRV2` Presence，编译不可变 topology snapshot。`max_peers` 是邻接上限，不是数据面队列调参。

## `[autotune]`

```toml
[autotune]
# mode = "shadow"          # off | shadow | on
# objective = "balanced"  # balanced | throughput | latency
# memory = true
# policy = "builtin"      # native | builtin | 绝对 .wasm 路径
# shadow_policy = "/etc/ironet/policy.candidate.wasm"
```

- 默认 `shadow + balanced + memory`，无需用户设置网络参数；规则基线继续在线应用，学习器只记录候选动作。
- `mode = "on"` 允许学习器应用经过 dwell、CPU、丢包和回滚护栏约束的动作；固定动作实验会强制关闭学习器。
- `policy` 有三层取值：
  - `native`：显式选择宿主保守规则（`native-conservative@1`），无学习器、不加载任何外部文件，effective 恒等于宿主规则基线；适合诊断或明确要求保守规则的部署。状态中的 `policy.policy_source` 标为 `native`。
  - `builtin`（默认）：在进程内运行 canonical `PolicySpecV1::builtin()` 的 `CorePolicy`（`bandit-vivace@1`）；带学习器，不初始化 Wasmtime，也不加载 `builtin.wasm`。状态为 `policy.policy_source=builtin`、`policy.live.backend=native`。
  - 绝对路径：外部 `.wasm` 策略组件（单文件 package，按 `[autotune.wasm]` 信任规则验签，见下节）；文件不可读、验签失败、ABI/资源预算越界时会回退到进程内 builtin core，不中断转发。**外部 JSON 策略 artifact 已移除**：指向 JSON 的绝对路径在配置校验时直接报错并提示迁移到签名 `.wasm` 组件。
- `builtin.wasm` 保留为和 in-process core bit-exact 的 guest fixture，也是可签名、可分发的外部组件模板；它不是 daemon 默认路径。若要部署该 guest，先签名并把生成的绝对 `.wasm` 路径写入 `policy`。
- `.wasm` 策略每 5 秒检查一次文件摘要；新摘要验证通过后，各 peer 在下一个 1 秒采样边界切换且不重建 QUIC 连接。候选在后台线程完成验签/编译/自检，切换前不阻塞调优节拍；坏文件保留 last-known-good。`policy_id` 相同且 `state_schema` 不变（或新模块的 `state_schema_accepts` 声明接受旧 schema）时学习状态随切换保留；旧版 JSON 内存文件中的 posterior/max-bw/min-rtt 可被 `bandit-vivace@1`（schema 相同）继承。
- `shadow_policy` 只接受绝对 `.wasm` 路径，加载失败时关闭 shadow 评估（不影响 live）。候选拥有独立的 context posterior、效用窗口和热切换状态；每秒计算完整候选 Action、posterior advantage 与候选权重下的 utility，但不写 BBR/FEC/调度参数。这里的 advantage 是离线 prior + 已观测线上动作形成的反事实估计，不冒充候选动作的实测吞吐。shadow 热切换从头开始（fresh state），仅影响观测面。
- `memory = true` 时，per-peer 后验原子写入身份文件同目录的 `autotune/`；同算法策略升级保留后验，不同算法只保留历史带宽和最小 RTT。
- `routing.max_egress_mbps` 会同时成为 BBR pacing 的硬上限，学习策略不能越过。

### `[autotune.wasm]`

```toml
[autotune]
policy = "/etc/ironet/policy.wasm"
shadow_policy = "/etc/ironet/policy.next.wasm"

[autotune.wasm]
require_signature = true                   # 生产默认；为 false 时必须给出 digest_pins
maximum_module_bytes = 8388608
maximum_memory_bytes = 8388608
maximum_state_bytes = 65536
deadline_millis = 100
state_flush_interval_secs = 60

[[autotune.wasm.signers]]
signer_id = "ops-2026"
public_key = "ed25519:BASE32..."
minimum_policy_version = 3                 # 防回滚下限
# expires_at = "2027-01-01T00:00:00Z"      # 可选

# 开发模式替代方案（require_signature = false 时生效）
# digest_pins = ["blake3:..."]
```

WASM 策略组件的信任根、资源预算和状态落盘配置。整段可省略（取默认值）；只有 `policy` 或 `shadow_policy` 指向 `.wasm` 时信任规则才会生效。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `require_signature` | `true` | 生产默认要求组件签名能被下方 signer 验证。为 `false` 时改用 `digest_pins` 精确匹配。 |
| `maximum_module_bytes` | `8388608` | 组件文件大小上限（字节），必须非零。 |
| `maximum_memory_bytes` | `8388608` | guest 线性内存上限（字节），必须非零。 |
| `maximum_state_bytes` | `65536` | 每 peer 不透明状态上限（字节），范围 1..=1048576（1 MiB）。 |
| `deadline_millis` | `10` | 单次 `decide` 的 wall 时限，范围 1..=1000。 |
| `state_flush_interval_secs` | `60` | 周期性状态落盘间隔，至少 1；模块切换、peer 断开和 daemon 退出时另行落盘，禁止每秒写盘。 |
| `signers` | 空 | 可信 signer 列表，可多条并存以完成密钥轮换；撤销即删除条目并重新 seal。 |
| `signers[].signer_id` | — | 非空且唯一，与组件签名段中的 `signer_id` 匹配。 |
| `signers[].public_key` | — | 形如 `ed25519:<key>`，key 为 32 字节公钥的 hex（64 字符）或 RFC 4648 base32（52 字符，可带 `====`）。 |
| `signers[].minimum_policy_version` | `0` | 防回滚下限：该 signer 签发的组件 `policy_version` 低于此值时拒绝。 |
| `signers[].expires_at` | 无 | 可选 RFC 3339 时间，到期后不再信任该 signer。 |
| `digest_pins` | 空 | 形如 `blake3:<64 hex>` 的组件摘要。仅 `require_signature = false` 时生效。 |

校验规则：`require_signature = true` 且配置了 `.wasm` 策略时至少要有一个 signer；`require_signature = false` 且配置了 `.wasm` 策略时 `digest_pins` 不能为空。模块自报的公钥不构成信任。

本段与 `policy`、`shadow_policy` 一起参与配置 seal：`ironet seal-config` 对整个主配置文件计算 BLAKE3 摘要，任何字段改动都需要重新 seal，guest 无法修改信任根。

## `[path_migration]`

```toml
# 高级运维护栏；通常整段省略
[path_migration]
pto_threshold = 4
min_pto_silence_ms = 250
min_silence_ms = 1000
max_silence_ms = 5000
recovery_probation_ms = 2000
recovery_max_response_gap_ms = 2000
recovery_min_responses = 3
health_ttl_secs = 300
rtt_switch_margin_ms = 5
keep_alive_ms = 250
idle_timeout_ms = 15000
```

- 默认仍是自动调优：失效期限按 `4 × 实测 RTT` 计算，再限制在 `min_silence_ms..max_silence_ms`；PTO 只作为提前信号。恢复必须连续收到针对该四元组的 PATH_CHALLENGE/PATH_RESPONSE 证明，并满足 `recovery_probation_ms`，跨路径 PATH_ACK 不会制造假恢复。
- 这些字段是部署期运行配置，不进入协议线格式。修改、密封并 reload 后即可生效，不需要重新编译，也不要求两端取相同值。
- `rtt_switch_margin_ms` 只抑制微小 RTT 抖动导致的切换；当前路径失效时会绕过该余量，立即选择健康路径。
- 配置加载时会拒绝零值、倒置的上下界，以及短于失效/恢复窗口的 `idle_timeout_ms`，防止错误参数把路径提前销毁。
- 真正改变 QUIC/V2 线协议、认证语义或数据结构时才需要重新编译和升级两端；普通阈值实验不需要。

## `[dns]`

```toml
[dns]
enabled = false
# domain = "n-example.ironet.internal"
# listen_port = 1053
# short_names = true
# accept_dns = true
# ttl_secs = 5
# reverse_prefixes = ["21.0.0.0/24", "21::/64"]
```

DNS 只消费通过认证的 V2 Presence 目录。启用时需要 `node_addresses`、`node_info`、`mesh.enabled = true` 和合法的 `domain`。

正式控制 socket 直接读取 V2 runtime state。旧 `[observability]`、`status_file`、`metrics_file` 和 `report_interval_secs` 配置均已删除，填写这些字段会被严格配置解析拒绝；Prometheus 文本由 `ironet metrics` 按请求从实时 snapshot 生成。

完整模板见 [`config/example.toml`](../config/example.toml)。
